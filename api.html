Do it programmatically

Generate from start & end frames via API

The same workflow used in Google Flow — a start frame, an end frame, and a descriptive prompt — can be driven programmatically through hosted model APIs. Pick a provider below, or use the snippet builder to draft a request for your own frames and prompt.

Option A — fal.ai

fal.ai hosts several image-to-video models that accept a start frame and an end/tail frame for interpolation (for example Kling's tail_image_url or Luma Ray2's end_image_url parameters). Check the specific model's page for the exact field names before you call it. 

curl -X POST https://fal.run/<model-id> \
  -H "Authorization: Key $FAL_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "image_url": "https://.../start-frame.png",
    "end_image_url": "https://.../end-frame.png",
    "prompt": "Developer typing in a terminal, text growing and colorizing, server lights changing",
    "duration": "8"
  }'
  • Upload local frames to any public URL first, or use fal's storage upload API.
  • Model IDs and parameter names vary per model — confirm on the model's fal.ai page.

Option B — Gemini / Veo

Google Flow itself has no public API, but the underlying Veo models are reachable through the Gemini API, which accepts a first frame image and, on newer Veo versions, a last frame for interpolation. 

curl -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/veo-3.1:predictLongRunning?key=$GEMINI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "instances": [{
      "prompt": "Developer typing in a terminal, text growing and colorizing, server lights changing",
      "image": { "bytesBase64Encoded": "<start-frame-base64>" },
      "lastFrame": { "bytesBase64Encoded": "<end-frame-base64>" }
    }]
  }'
  • Video generation is asynchronous — poll the returned operation until it completes.
  • Field names have changed across Veo releases — verify against current Gemini API docs.
